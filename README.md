# Noma Local

**在懂你的基础上，让家庭的智能家居更好地为你服务。**

本地连接版，目录为 `Noma Public`。**直接复用 Private 的 Next.js 前端页面、组件、样式与静态资源**，本地部署前后端，通过局域网连接 Home Assistant；Agent、模型、账号、记忆和订阅继续由 Noma Cloud 提供。

```text
浏览器 → 本地 Go 网关 :3100
          ├─ 页面 / 静态资源 → 本地 noma-web（原 Noma Next.js 前端）
          ├─ 账号 / 记忆 / 会话 API → HTTPS → Noma Cloud
          └─ HA 状态 / 控制 → 局域网 Home Assistant
```

不需要 FRPC / FRPS 或额外 Connector，不部署私有 Agent、Memory OS、模型 Key 或数据库服务。

## 前端复用范围

本地部署访问根路径 `/` 直接进入 Agent 对话页 `/agent`，宣传首页及其专用代码、依赖和素材已移除；未登录时先登录，完成后进入对话页。保留原介绍、登录、对话、记忆、家庭、设置与法律页面，以及侧栏、会话列表 / 搜索 / 切换 / 排序、消息滚动、设备卡片和乐观更新等原有实现。

适配集中在连接层：

- 浏览器统一请求同源 `/api/v1`，网关按方法 / 路径白名单代理到云端或本地 HA。
- 云端 JWT / refresh Cookie 留在后端。前端原 access_token 变为会话存在标记；实际鉴权依赖本地 HttpOnly Cookie。
- 原对话发送复用云端 Agent 的增量回复，网关即时转发原页面接收的 SSE 事件；Local 工具循环仅把设备执行放在本地。通过 `Accept: text/event-stream` 协商增量事件，同时兼容旧 JSON 响应。
- HA 设置沿用原设置布局，默认只需填写 Token 并点击“连接”，自动允许全部实体；自定义地址位于折叠设置中。
- 本地实例必须先通过原登录页登录 Noma 云端账号，才可进入页面和使用 API；不提供游客模式。连接 HA 时同时启用当前浏览器的设备访问，不需要额外访问密钥。

## Docker 启动

```bash
docker compose up -d --build
```

这是唯一的本地运行方式。前端容器运行 `next dev`，保存页面后通过网关热更新。后端容器轮询 `cmd`、`internal`、`go.mod` 和 `go.sum`，忽略 `*_test.go`；Go 文件变更后先编译，成功才切换网关进程，编译失败时旧进程继续运行。登录状态保存在后端数据卷中，重启后可恢复。无需创建 `.env`，也不需要生成访问密钥。默认云端为 `https://noma-ai.cloud`，本地仅监听 `127.0.0.1:3100`。Docker Hub 拉不到 Node 镜像时，可在 shell 中临时把 `NOMA_DEV_NODE_IMAGE` 设为可用镜像源后再构建。

访问 [http://localhost:3100](http://localhost:3100)，先登录 Noma 云端账号。其余页面和业务 API 仍要求有效登录会话；在设置 → Home Assistant 中填写 HA 长期访问令牌并连接后，可访问该 HA 的全部实体，设备控制仍受服务与参数白名单约束。Compose 启动前后端两个服务，仅网关对外映射端口。

本地登录使用 HttpOnly Cookie，空闲有效期为 30 天，使用时最多每天续期一次；云端凭证过期由后端自动刷新，云端撤销凭证后仍需重新登录。access / refresh 凭证及其到期时间只保存在配置文件同目录的 `sessions/`（默认 `data/sessions/`，Docker 为 `/data/sessions/`），文件名使用本地会话 ID 的摘要，文件权限为 0600；浏览器只持有随机本地会话 Cookie。重启后复用尚有效的 access 凭证，避免每次重启都立即刷新。退出登录会删除对应文件并清除 Cookie。不要提交或分享该目录；删除数据卷会丢失登录状态。网络或云端临时故障不会被当作退出登录。已保存的设备授权绑定 HA 地址、令牌及实体范围；配置不变时可随登录恢复，配置变化时需重新连接。旧版未记录设备授权的会话需点击一次“连接”，以后即可恢复。

## 可选的 HA 配置

云端地址、端口和本地 HTTP Cookie 策略都有默认值。不连接 HA 时无需配置文件。连接时在设置 → Home Assistant 中粘贴 HA 长期访问令牌并点击“连接”，后端验证成功后保存到 `data/local.json`（Docker 为 `/data/local.json`），立即生效，无需重启。页面不读取或回显已保存的 Token；以后留空即可继续使用。

连接成功后，设置页沿用原版的连接状态卡片、上次连接时间及家庭名称表单。名称保存到本地配置的 `home_name`，上次连接时间保存为 `ha_connected_at`；名称未修改时禁用“保存”，保存后同步“家”页面标题。检测到连接不可用时，页面直接切回连接表单，保留已保存的 HA 地址，令牌可留空沿用后端配置；恢复连接后显示已连接页面。

HA 地址默认是 `http://localhost:8123`，原生与 Compose 一致。`localhost` 指 Noma 后端所在的运行环境；Docker 部署时指后端容器自身。HA 不在同一运行环境时，在“自定义 Home Assistant 地址”中填写后端可访问的 HA 局域网地址，例如 `http://192.168.1.100:8123`。`NOMA_HA_URL` 可覆盖默认地址，配置文件或页面中明确保存的地址优先。

设置页连接默认允许全部实体，包括之后新增的实体；后端以 `allowed_entities: ["*"]` 保存此模式。每次读取使用 HA 的当前实体列表，控制前确认目标实体存在，服务和参数白名单保持不变。页面不再提供授权设备输入框；手动配置或本地 API 仍可指定实体 ID 数组限制范围，显式 `[]` 不授权任何实体。页面重新连接会恢复全部实体模式；修改连接或授权范围后，其他浏览器需要重新连接确认。

“家”页面按家庭设备用途筛选：保留灯、开关、家电及常用环境 / 安防传感器，隐藏备份、太阳时间、手机遥测、诊断和配置实体；关闭或离线的家庭设备仍显示，传感器只展示状态。该规则仅影响设备目录及页面摘要，不改变 HA 中的实体或执行器授权范围。

区域来自 HA 的实体、设备及区域登记信息：实体单独指定的区域优先，其次使用设备（含父设备）区域；未分配区域的设备单独分组。手机集成实体和功率、电量、电流、电压等附属读数不作为独立设备卡片展示。登记信息只在本地读取，每分钟更新；临时失败保留上次结果，30 秒后再检查，不修改 HA 配置。

设置页和“家”页面切换时先显示当前账号的缓存，再后台读取状态；连接状态和打开的家页面每 10 秒检查一次。设置页连接缓存保存在浏览器本地存储，设备列表保存在当前标签页会话存储（最长 24 小时），不缓存 HA Token。网络暂时失败保留上次数据，明确断开时更新连接状态；后台更新保留尚未保存的家庭名称和正在操作的设备状态。

也可以直接在本地后端创建配置文件。以下仅为手动配置示例，不要把真实配置提交到 Git：

```json
{
  "ha_url": "http://localhost:8123",
  "ha_token": "<你的 HA 长期令牌>",
  "allowed_entities": ["*"]
}
```

原生后端默认读取 `data/local.json`。Docker 后端读取持久化数据卷中的 `/data/local.json`；手动修改文件后需重启，也可执行 `docker compose cp data/local.json noma-local:/data/local.json`、`docker compose restart noma-local`。Token 只由浏览器一次性提交给同源本地后端，后端不会向浏览器或云端返回 Token。页面保存使用私有临时文件替换原配置；建议限制本地数据目录的读取权限。手动配置的空白名单不授权任何设备。

高级部署可在同一 JSON 文件中覆盖 `listen`、`cloud_url`、`web_url`、`secure_cookie`。原生监听默认 `127.0.0.1:3100`；Docker 对外绑定和映射端口在 `compose.yaml` 中修改，容器内部路由由 Compose 自动设置。手机访问需明确允许局域网绑定；所有能访问实例并登录的受信任家庭用户均可自行启用该实例的设备范围。需要本地 HTTPS 时设置 `secure_cookie: true`，代理保留 Host。当前 Host 仍仅接受 IP / localhost。

Google 登录从本机跳到 `https://noma-ai.cloud/local/authorize`，不在本地加载 Clerk，也不需要 Clerk Key。官网完成登录后带回两分钟有效的一次性授权码，只由本地后端通过 PKCE 兑换。生产 Clerk 实例因此不必把 `localhost` 加为 Web 来源。云端需部署包含官网授权页及 `/api/v1/local/oauth/authorize`、`/api/v1/local/oauth/token` 的版本。HA Token 单独保存在本地后端配置文件中，不使用共享默认凭证。

局域网 HTTP 会明文传输凭证和对话；手机录音等浏览器能力需要安全上下文，正式家庭部署建议本地 HTTPS。服务需持续运行，初版不提供离家远程访问部署方案。

## 原生开发

需要 Go 1.25+、Node.js 22.13+。Go 使用 `github.com/coder/websocket` 读取 HA 的区域与设备登记信息，依赖版本由 go.mod / go.sum 固定；前端沿用原 package-lock.json。无需 `.env`；可选 HA 配置由 Go 后端读取。

终端 1 启动前端：

```powershell
cd noma-web
npm ci
npm run dev
```

终端 2 在根目录启动网关：

```powershell
go run ./cmd/noma-local
```

浏览器访问网关端口 3100，前端开发端口 3001 仅供网关访问；直接打开 Next.js 端口不具备本地 API 路由。

```text
noma-web/           复用的 Next.js 前端、原组件 / 样式 / 资源 / 测试
cmd/noma-local/     Go 网关入口
internal/app/      本地会话、原 API 适配、云端代理和工具循环
internal/cloud/    云端认证与 HTTP 客户端
internal/ha/       HA 白名单及执行器
internal/protocol/ 云端远程工具协议
```

## 验证与边界

```bash
go test ./internal/... ./cmd/...
go vet ./internal/... ./cmd/...
go build ./cmd/...
cd noma-web
npm test
npm run build
```

上述命令即可做基本回归；测试不发送真实验证码、不控制真实设备。

实例面向一个受信任家庭，共享本地 HA 授权范围，云端凭证按浏览器会话隔离。登录采用 30 天可续期的持久化会话，网关重启保留登录及与当前配置一致的 HA 授权。退出账号同时撤销当前浏览器的 HA 授权，下次登录需重新点击“连接”，无需重填已保存的 Token。历史会话通过原云端 API 加载，不再读写或自动导入游客历史。

工具去重覆盖同一本地会话 / request_id，每会话 128 轮，单轮 16 个不同工具、8 次云端往返。请求开始前先持久化请求 ID 与内容摘要，不保存消息或工具结果；重启后相同请求返回 409 并提示检查设备状态，不重新执行。完整结果缓存仍在内存中，不承诺跨崩溃恰好执行一次；生产仍需实例 / 家庭绑定和更完整的恢复机制。

仅复用用户要求的前端及资源，未复制 Private 核心后端、环境文件或 Git 历史。经用户明确授权，仅在 Private 补齐本地 Google 授权登录，以及 Google 默认昵称 / 缺失头像补全和相关测试；云端前后端发布后重新 Google 登录一次即可触发补全，本地账号页继续读取同一份云端资料。公开发布前由项目所有者确定许可证与资源授权，本次未擅自选定授权条款。
